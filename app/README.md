# Controlled mobile app

Expo React Native client for Controlled, targeting Android and iOS. The current UI implements the supplied onboarding reference through the initial greeting screen. Google and email/password authentication exchange verified credentials for a Controlled session. Email OTP verification is intentionally deferred.

## Run locally

Use Node 24, then install dependencies and start Expo from this directory:

```bash
nvm use
npm install
npm run android
```

Google sign-in uses native modules, so it requires a development build and does not run in Expo Go. After the first native build, start Metro with:

```bash
npm start
```

Use `npm run ios` to create and run the iOS development build.

The Android emulator reaches the local API at `http://10.0.2.2:8080` by default; iOS uses `http://127.0.0.1:8080`. For a physical device or hosted API, set `EXPO_PUBLIC_API_URL` before starting Expo:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.20:8080 npm start
```

## Checks

```bash
npm run lint
npm run typecheck
npx expo-doctor
```

The native application identifiers are `com.fromh.controlled` on both platforms. Native `android/` and `ios/` projects are generated by Expo when needed and are intentionally not committed.

## Android system notifications

The app registers an authenticated device with the Controlled API and deep-links payment requests, pact-break decisions, and invitations into their existing screens. There is no notification inbox.

Complete the one-time native setup before testing real pushes:

1. From this directory, run `npx eas-cli@latest init` to create or link the Expo project. This writes `extra.eas.projectId` to `app.json`. For local development you may instead set `EXPO_PUBLIC_EAS_PROJECT_ID` to that UUID.
2. In Firebase, add the Android app `com.fromh.controlled`, download `google-services.json` into this directory, and add `"googleServicesFile": "./google-services.json"` under `expo.android` in `app.json`.
3. Create an FCM V1 service-account key. Run `npx eas-cli@latest credentials`, then choose Android, the build profile, Google Service Account, and upload the key for push notifications. Never commit the service-account key.
4. Rebuild and reinstall the native app with `npm run android` (or an EAS development build). A Metro reload cannot add the native notification configuration to an already installed binary.

The app asks for notification permission after sign-in. The backend needs no Firebase key because it sends through Expo Push Service; only the EAS project holds the FCM V1 credential.
